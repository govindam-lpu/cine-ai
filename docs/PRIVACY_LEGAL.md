# Cinerex — Privacy & Legal Notes

This document is not a formal legal document. It is a set of binding operational rules and notes for the development team covering data handling, privacy, and legal considerations. Before public launch, a proper Privacy Policy and Terms of Service must be drafted by a legal professional or using a reputable legal template service.

---

## Data We Collect

### What Cinerex stores:

| Data | Source | Why |
|---|---|---|
| Letterboxd username | User input | To identify and scrape their profile |
| Serializd username | User input (optional) | Same |
| Film watch history (titles, ratings, dates) | Scraped from public profiles | Core functionality |
| Written reviews | Scraped from public profiles | Taste profiling |
| Watchlist | Scraped from public profiles | Watchlist ranker feature |
| AI-generated taste profile | Generated by Cinerex | Recommendations |
| Email address | User input (optional) | Account persistence |
| Country code | User input or IP detection | Streaming availability |
| Streaming service preferences | User input | Filter recommendations |
| Post-watch reflections | User input (optional) | Improve taste profiling |

### What Cinerex does NOT store:
- Letterboxd or Serializd passwords (never requested)
- Payment information (no payments at launch)
- IP addresses (beyond standard server logs)
- Device fingerprints
- Browsing history outside of Cinerex
- Any data about users who have NOT signed up for Cinerex (compatibility mode uses scraped data only for the analysis session — it is not persisted to a permanent profile)

---

## Data Usage

All collected data is used **only** to provide Cinerex's core features to the individual user. It is:
- Not sold to third parties
- Not shared with advertisers
- Not used to train AI models (data is passed to the Claude API for inference only — Anthropic's data usage policies apply)
- Not used to build profiles for anyone other than the user themselves

## Scraping & Third-Party ToS

### Letterboxd
- Letterboxd's Terms of Service prohibit automated scraping without permission.
- Cinerex scrapes public profile data to provide a service to the profile owner — this is a gray area that many apps operate in.
- **Mitigation:** Scrape only public data, at respectful rates, for the user's own benefit only.
- **Risk:** Letterboxd may send a cease-and-desist or block scraping. If this happens, stop immediately and explore the Letterboxd API (they have a private API with limited access — apply for it).
- **Recommended pre-launch action:** Apply for official Letterboxd API access at `letterboxd.com/api-beta/`.

### Serializd
- Serializd is a smaller platform — less likely to take action.
- Same approach: public data only, respectful rate limiting.

### TMDB
- TMDB has a free public API with clear terms of service.
- Usage is permitted for non-commercial apps with attribution.
- Required attribution: "This product uses the TMDB API but is not endorsed or certified by TMDB."
- Display the TMDB logo in the app footer or about page.

## User Rights

Cinerex must support the following user rights before public launch:

1. **Right to access** — User can request a full export of their data
2. **Right to delete** — User can delete their account and all associated data permanently
3. **Right to correct** — User can re-sync or override scraped data
4. **Right to opt out** — User can opt out of the Film Twin feature (data not used for matching)

Implement a "Delete my account and all data" button in Settings. When triggered:
- Delete all rows in all tables where `user_id = this_user`
- Delete Supabase Auth account
- Confirm deletion to the user

## GDPR / Indian Privacy Law Considerations

If users are based in the EU: GDPR applies. Key requirements:
- Explicit consent for data collection
- Right to erasure must be honored within 30 days
- Data Processing Agreements with all third-party processors listed above

If users are based in India: The Digital Personal Data Protection Act (DPDPA) 2023 applies. Key requirements:
- Consent-based data processing
- User must be able to withdraw consent and request erasure
- Appoint a Data Protection Officer if processing at scale

**At MVP scale:** Focus on building the deletion flow and data export flow. Full GDPR/DPDPA compliance can be hardened when user base grows.

## Security Notes

- All API keys stored as environment variables — never hardcoded or committed to git
- Supabase Row Level Security (RLS) enabled on all user data tables
- HTTPS enforced on all endpoints
- Supabase service key (admin access) only used server-side in the FastAPI backend — never exposed to the frontend
- Frontend only uses Supabase anon key (limited by RLS)
- User inputs sanitized before any database writes or LLM calls
- Prompt injection: when passing user-generated text (reviews, reflections) to the LLM, wrap in clear delimiters and instruct the model to treat it as data, not instructions
